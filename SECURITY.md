# Security

Use GitHub private vulnerability reporting when enabled. Do not attach credentials, device private keys, policy files, ledgers, session content, tunnel profiles, or raw journals to public issues.

This is an experimental single-owner bridge. Keep transport private. The caller's MCP access is powerful: enabled session tools can delegate model work under the configured owner's visibility and limits. Never share an instance across owners.

The repository excludes live state and historical deployment evidence. Tests generate temporary identities; they do not require production credentials. Changes must preserve exact scopes, owner verification, native visibility, fail-closed grants, and non-replay of uncertain operations.
